# Santara migration handoff

Branch: `tauri-rt`. Tauri 2 is the sole desktop host on this branch; the earlier Electron code remains in Git history. The user authorized code work through the migration before final native checks and authorized Electron removal on this branch. Do not add macOS support or touch the untracked user-owned `design/` directory. Do not use sudo to install packages; the user handles system packages.

The workspace, citrus wheel, editors, local Rust jobs, optional backend detection, Windows watcher, GNOME extension, and Windows/Linux package configuration are implemented. The wheel now requires two complete taps of the configured Shift, Alt, or Ctrl modifier during an active drag, each tap and the gap between taps within 400 ms. A key held before drag begins cannot count as the first tap. The workspace picker also uses double taps. A single press does not open the wheel. The optional platform helpers match this behavior. A global wheel drop without a selected slice now hands inspected files to the workspace; native and DOM drop callbacks are guarded against empty/duplicate events. Wheel hide after drag release allows 600 ms for the native drop event. Image editor directional pan now responds at low zoom. These changes still need real file-manager validation.

Checks for the previous double-tap update: TypeScript/Vite build and Rust/native protocol tests pass; Windows helper cross-build and Wine state self-test pass; GNOME syntax/schema checks pass. All 20 browser tests pass, covering double tap, single press, wheel drop, workspace handoff, editors and queue. The earlier `.deb` and AppImage builds have measured actual installer sizes and hashes in [packaging](docs/TAURI_PACKAGING.md). `npm run release:report` completed; its generated inventory files were not retained in the repository. The previous installed Santara package is older than these source changes and must be reinstalled to see them.

The local GNOME 50 extension files and command template were refreshed without sudo. GNOME currently reports it `ACTIVE`, but a logout/login may still be needed for the Shell process to reload updated extension code. Check with `gnome-extensions info santara-wheel@santara.local`. The installed Santara `.deb` is also older; reinstall the rebuilt package before testing real drags. Do not force-restart the user's Wayland session.

After a user screenshot showed "Image editor is no longer available", the hidden editor lifecycle was corrected: image/video hosts now accept a fresh private context event on each open and reset each editor session. Repeated file drops retain stable IDs and refreshed metadata. The global wheel shows Activity after a successful queue, returns failed drops to the workspace with a notice, and hides the unavailable native Share action. Rust/native protocol tests and all 25 browser tests passed. The current `.deb` and AppImage were built and measured in [packaging](docs/TAURI_PACKAGING.md); the AppImage passed a 12-second isolated startup smoke test. An older `/usr/bin/santara` process was observed still running and was left untouched because it may own local jobs. Quit it before testing the new package.

Phase 8 remains open. Run the native [validation checklist](docs/TAURI_VALIDATION_CHECKLIST.md) on Ubuntu LTS x64 and Windows 10/11 x64 with real GNOME Files/Explorer drags, package install/uninstall, backend fixtures, accessibility, offline operation and measured installed sizes. Wine is a helper self-test only and does not satisfy Windows acceptance. The detailed gaps are in [the parity matrix](docs/TAURI_PARITY_MATRIX.md). Do not claim feature parity or release readiness until those gates pass. Generate final artifact sizes and dependency inventory with `npm run release:report`; do not call package metadata an installed-size measurement.

The latest wheel fix was checked with `npm run typecheck`, `npm run test`, `npm run build`, `npm run test:e2e`, `npm run build:windows-hook:cross`, and `npm run check:release`. The full Windows NSIS installer cannot currently be built on this Ubuntu host: `lld`, `llvm`, `nsis`, `clang`, `rustup`, the Windows MSVC Rust target, and `cargo-xwin` are absent. The required sudo packages are documented in [build instructions](docs/BUILD.md); rustup should be installed per user because its Ubuntu package conflicts with this host’s system Rust packages. The current `.deb` has not been installed, so its installed footprint and real GNOME drag behavior remain unmeasured. Do not confuse the measured extracted package payload with installed size.
